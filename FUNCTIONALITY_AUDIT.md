# Functionality audit

Date: 16 November 2026.

The tested navigation, workflows, read APIs, filters, exports, and shared controls pass after the fixes below. This report describes the checks performed; it does not claim that every possible record state or simultaneous-user interaction has been exercised.

| Workflow and API checks in an isolated database | 44 passed |

Roles checked: administrator, executive, mayor, chairman, planner, enforcement officer, revenue officer, and vendor. All displayed navigation destinations responded successfully for the account that displayed them.

Workflow checks include sign-in/sign-out, invalid CSRF rejection, role permission rejection, registration validation retaining entered values, vendor creation and editing, footfall recording, pitch editing, land-use restrictions, appearance preferences, notices, account-data export, CSV exports, and read APIs for maps, stall availability, matching, role dashboards, notifications, and live updates. Unknown-action checks verify that eleven mutation endpoints refuse unsupported requests without server errors; these are not substitutes for exercising every supported action.

The allocation workflow was exercised through offer, accept, occupy, withdraw, repeat-withdraw refusal, decline, and refusal to withdraw an already declined offer. Tests verify both market counters and the vendor's resulting stage.

Shared-control checks cover desktop navigation, grouped navigation, account-menu open/outside-click/Escape behavior, theme persistence, guidance, role dashboard, print dispatch, mobile drawer/backdrop/Escape, and modal focus and close behavior. These run against the actual rendered vendor page and shared scripts using a DOM implementation.

## Fixes made

- Allocation offers now return an actionable validation message when the vendor has no recorded trading location, instead of raising an undefined-coordinate server error.
- Allocation distance and criterion calculations use the shared coordinate accessors consistently.
- Withdrawing a placed allocation now removes its registration from the market total and updates the vendor stage. Already closed allocations cannot release vacancy a second time.
- Account-menu outside-click and Escape dismissal now reset `aria-expanded`; Escape also restores focus to the account button.
- The language checker uses the running PHP executable, allowing its checks to work with XAMPP when `php` is absent from PATH.

## Data handling and test artifacts

Mutation checks ran against a separate copy of the local database on a temporary PHP server at port 8082. They did not create test vendors, offers, notices, restrictions, or footfall records in the working database. Read checks and sign-ins against the working app can create normal authentication audit entries.

The temporary server, isolated database, generated backup, session files, and raw HTML fixtures were removed after verification. Machine-readable summaries and the diagnostic scripts remain in `.ui-review/`. The control script expects HTML fixtures generated by the navigation audit; write tests require an isolated server/database to be prepared again before rerunning them.

## Verification limits

The environment did not permit launching the graphical browser. Native browser rendering, real print-dialog behavior, and complete visual click-through remain unverified. Backup creation passed; a complete backup restore was not tested. Concurrent allocation requests, every bulk-planning scenario, and external websites were not exercised.
